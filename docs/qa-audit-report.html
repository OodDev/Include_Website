01Summary

The specification PDF remains the single source of truth for site architecture, navigation and copy. The audit found the website already closely aligned with it; the review surfaced ten real discrepancies, all of which have been fixed and committed (commit 0a0251c):

  • 1 broken navigation behaviour — mobile menu links silently produced wrong URLs from nested pages;
  • 3 dead links — CTAs pointing at an anchor (#ambassador-network) that did not exist on the target page;
  • 2 missing sentences of approved PDF copy that were silently not rendered (Ready for Inclusion lead paragraph; Home link in the footer menu);
  • 4 copy/wording mismatches — truncated phase headings, a mislabelled card CTA, a misleading button label and non-PDF quotation marks in a partner name.

Nothing was invented to fill gaps: every fix either restores the exact PDF wording or reuses wording already approved elsewhere on the site.

02Fixes applied, by category

Links & navigation

  • Mobile menu — broken relative links. Menu items used relative URLs (href="the-project"), which the browser resolves against the current page. From any nested page (e.g. a news category page) tapping “The Project” produced a wrong URL and a 404. Links are now absolute and locale-aware, verified at runtime from the home page, inner pages and a dynamic route, on both mobile and desktop viewports.
    src/components/layout/MobileNav.tsx
  • Footer menu — “Home” restored. The PDF’s site-wide recommended menu begins with HOME; the footer omitted it (only the logo linked home). The footer now reads exactly: Home · The Project · The Pathway · Results & Tools · Ready for Inclusion · Partners · News · Contact. A dead “glossary” code branch was also removed.
    src/components/layout/Footer.tsx
  • Missing anchor #ambassador-network. Three calls-to-action pointed to /ready-for-inclusion#ambassador-network (the “Why companies?” CTA and the network band on the home page — in both English and Italian content) but the target section carried no anchor, so the links scrolled nowhere. The section now has the matching anchor with correct scroll offset.
    src/app/[locale]/ready-for-inclusion/page.tsx
  • News cards — locale-aware links. Story cards used raw anchors (<a href="/news/…">) without the language prefix, causing an extra redirect for every click. Now the standard locale-aware link component is used.
    src/app/[locale]/news/page.tsx

Copy — word-by-word vs. the PDF

  • Missing approved sentence restored. “The Ready for Inclusion initiative will provide companies with a structured pathway to understand their readiness, strengthen inclusive practices and make their commitment visible.” was present in the approved content file but never rendered: the page read a non-existent field (hero.sub) while the text is stored one level up. The paragraph now appears under the page heading, exactly as in the PDF.
    src/app/[locale]/ready-for-inclusion/page.tsx
  • Pathway phase headings — full PDF names. A formatting rule truncated the headings to “Protected”, “Pre-corporate” and “Work-based learning”, dropping the PDF’s key terms. They now read verbatim: “Protected Gym”, “Pre-corporate preparation”, “Work-based learning in SMEs”.
    src/app/[locale]/the-pathway/page.tsx
  • Partner name typography. “G. d’Annunzio” now uses the typographic quotation marks shown in the PDF.
    content/data/partners.yaml
  • News card labels. Every story card’s link read “All stories” — the label of the back-link at the end of an article, repeated on every card. Cards now say “Read more”; “All stories” remains where it belongs (article back-link).
    src/app/[locale]/news/page.tsx, src/app/[locale]/news/category/[category]/page.tsx
  • Home “What the project produces” button. It said “Discover the project” (the hero CTA label, which correctly links to The Project) but pointed at Results & Tools. Relabelled “Download resources” — the PDF’s suggested CTA for the outputs repository — reusing the already-approved translation key.
    src/components/sections/HomeSections.tsx

Consistency

  • Project targets rendered verbatim. The Ready for Inclusion page paraphrased the targets (“400 SMEs reached”, which read like an achievement). Both sentences are now rendered word for word from the approved text — “The project aims to involve up to 20 companies per partner country…” and “…to reach at least 400 SMEs…” — keeping the project aims clearly labelled as aims.
    src/app/[locale]/ready-for-inclusion/page.tsx
  • Dead content reference removed. The Project page carried a reference to a translation key (pages.paragraphs.gapTitle) that exists in no language and is never rendered; removed to keep the content clean.

04Design & style changes made (and why)

Deliberately minimal — only what was needed for the corrected copy or structure to sit well in the existing layout. No redesign, no unrelated visual changes:

  • Restored full phase headings on The Pathway received a line-width constraint so the longer names wrap cleanly inside the existing two-column layout.
  • The Ambassador Network section inherited the site’s standard anchor scroll offset so browser-back and CTA jumps land with the heading visible below the sticky header.
  • The hero section and the fact cards overlapping the hero were not touched, as requested.

06Ambiguities — please confirm with the client

Decision 1 — desktop menu order

The PDF’s recommended menu places Ready for Inclusion fourth (after Results & Tools). In the desktop header it is rendered as the highlighted pill at the end, following the approved design mockups; the footer and the mobile menu follow the PDF order exactly. The current arrangement is a documented, deliberate compromise — please confirm, or ask for the strict PDF order in the header too.

Decision 2 — hero second button

The PDF’s hero suggests a single CTA (“Discover the project”). The site also shows “I am a company” next to it, which comes from the approved design mockups and strengthens the companies entry point. Kept as is — please confirm.

Decision 3 — extra home sections

The PDF describes a deliberately concise home (promise → why → three ambitions → manifesto → stay connected). The page additionally contains the three-phase pathway teaser, audience cards, “What the project produces” and the network band. These come from the approved home mockups and are consistent with the PDF’s note that detailed content lives on secondary pages — please confirm they should remain.

Decision 4 — pending-approval micro-copy

Two short home-page lines (the pathway teaser subtitles and the statement pull-quote) are mockup-derived translations explicitly flagged in the content for client sign-off. They are rendered as drafted; please review the wording.

07What could not be verified

  • Production domain in page metadata. Canonical/share-preview URLs fall back to a localhost address unless the site’s public URL variable is set in the hosting environment. Please confirm it is configured on the live deployment.
  • security.txt expiry. The file’s expiry date has already passed; it should be renewed together with the real security contact (see placeholders).
  • Italian, Portuguese, Spanish and Greek drafts. Intentionally not published yet, so they were not word-diffed; message-level parity across all five languages was verified automatically.
  • Live third-party integrations (newsletter, consent statistics) — correctly switched off without credentials, so their behaviour with real providers could not be exercised.
